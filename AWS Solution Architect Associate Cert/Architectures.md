> [!abstract] What is it?
> **Architectures and Exam Preparation** focuses on understanding how AWS services are combined to build reliable, secure, and cost‑effective systems, and how AWS evaluates those designs using established best practices.

---

## AWS Well‑Architected Framework
The Well‑Architected Framework defines how to design and operate systems in the cloud. It is not about specific services, but about architectural decisions and trade‑offs.

### The six pillars
- **Operational Excellence**: running and monitoring systems, improving processes
- **Security**: protecting data, systems, and assets
- **Reliability**: recovering from failures and meeting demand
- **Performance Efficiency**: using resources efficiently
- **Cost Optimization**: avoiding unnecessary spend
- **Sustainability**: minimizing environmental impact

Each pillar provides principles that guide design choices rather than prescribing exact implementations.

---

## AWS Well‑Architected Tool
The Well‑Architected Tool evaluates workloads against the framework.

It asks structured questions across all pillars and identifies risks as high‑risk or medium‑risk issues. The output includes improvement plans and recommended best practices.

This tool is used to review architectures, identify weaknesses, and track improvements over time.

---

## AWS Trusted Advisor
Trusted Advisor analyzes an AWS environment and provides recommendations.

It focuses on:
- Cost optimization
- Security
- Fault tolerance
- Performance
- Service limits

Trusted Advisor continuously checks configurations and highlights opportunities to improve efficiency and reduce risk.

## Common Architecture Patterns

### Highly available web application
- Load balancer distributes traffic
- Auto Scaling group spans multiple AZs
- Stateless application tier
- Managed database with replication

This pattern tolerates instance and AZ failures.

---

### Event‑driven architecture
- Events generated by services or applications
- Event routing through EventBridge or SNS
- Processing via Lambda or container tasks

This design decouples components and scales naturally.

---

### Data processing pipeline
- Ingestion through streaming or batch services
- Storage in S3 or data stores
- Processing using analytics or compute services
- Visualization or downstream consumption

This pattern supports large‑scale analytics and reporting.

---

## Exam Preparation Mindset
Architectural questions test understanding of trade‑offs rather than memorization.

- Choose managed services when possible
- Design for failure and recovery
- Minimize operational overhead
- Balance cost, performance, and resilience

Understanding why an architecture works is more important than knowing every feature.
