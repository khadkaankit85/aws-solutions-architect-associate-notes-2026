> [!abstract] What is it?
> **Monitoring and Audit on AWS** provides visibility into system health, performance, security, and configuration changes. These services answer three core questions: what is happening now, what happened in the past, and is the environment compliant with expected rules.

---

## Amazon CloudWatch

CloudWatch is the primary service for **operational monitoring**. It collects metrics, logs, and events from AWS resources and applications and turns them into actionable signals.

### CloudWatch Metrics
Metrics are numerical time‑series data emitted by AWS services and custom applications.

- Examples include CPU utilization, request count, latency, and error rates
- Metrics are stored at regular intervals and retained for analysis
- Custom metrics allow applications to publish their own measurements

Metrics are used to understand system behavior over time and to trigger alarms when thresholds are crossed.

---

### CloudWatch Logs
Logs store unstructured or semi‑structured text generated by applications and services.

- Services like Lambda, ECS, and API Gateway automatically publish logs
- Logs are grouped into log groups and streams
- Logs can be searched, filtered, and retained based on policy

Logs provide detailed context for debugging and incident investigation.

---

### CloudWatch Logs Agent
The CloudWatch Logs Agent runs on EC2 or on‑prem servers to push logs into CloudWatch.

- Collects OS logs, application logs, and custom files
- Enables centralized logging for non‑AWS‑native workloads
- Required when logs are not emitted automatically by AWS services

---

### CloudWatch Alarms
Alarms evaluate metrics and take action when conditions are met.

- Trigger notifications through SNS
- Can invoke Auto Scaling actions
- Used to detect failures, performance degradation, or capacity issues

Alarms convert raw metrics into operational responses.

---

### CloudWatch Network Insights
Network Insights analyzes VPC networking paths.

- Identifies reachability issues
- Diagnoses security group, route table, and NACL problems
- Used for troubleshooting connectivity failures

---

### CloudWatch Synthetics
Synthetics uses canaries to simulate user behavior.

- Periodically runs scripted tests
- Monitors endpoints, APIs, and user flows
- Detects issues before real users are impacted

This provides proactive monitoring from an external perspective.

---

### CloudWatch Insights and Operational Visibility
CloudWatch Insights enables interactive querying and analysis.

- Logs Insights allows SQL‑like queries over logs
- Metrics Insights enables advanced metric analysis
- Dashboards combine metrics, logs, and alarms into a single view

These tools provide deep operational visibility across distributed systems.

---

## AWS CloudTrail

CloudTrail records **API activity and account actions**.

- Logs who performed an action
- Records what action was taken
- Captures when and from where it occurred

CloudTrail events are immutable audit records and are typically stored in S3.

---

### CloudTrail EventBridge Integration
CloudTrail events can be sent to EventBridge in near real time.

- Enables automated responses to API activity
- Supports security automation and compliance workflows
- Allows filtering and routing of events to Lambda, SNS, or SQS

This turns audit data into actionable events.

---

## AWS Config

AWS Config tracks **resource configuration state** over time.

- Records configuration changes
- Maintains a history of resource states
- Evaluates resources against rules

Config answers whether resources are configured correctly and remain compliant.

---

### AWS Config Rules
Rules define desired configuration states.

- Managed rules provided by AWS
- Custom rules using Lambda
- Continuous or periodic evaluation

Non‑compliant resources are flagged for remediation.

---

## CloudTrail vs CloudWatch vs AWS Config

| Service | Focus | Answers |
|---|---|---|
| CloudWatch | Operational health | How is the system performing right now |
| CloudTrail | API activity | Who did what and when |
| AWS Config | Configuration state | Is the environment compliant |

---

## Mental Model Summary
- CloudWatch monitors **performance and health**
- CloudTrail audits **actions and access**
- AWS Config enforces **configuration correctness**

Together, these services provide full observability, security auditing, and compliance tracking.
